# SIERRA SDK

Public, read-only clients for the [SIERRA Grid API](https://data.sierragridteam.org/api/openapi.json). TypeScript is available first; Python and Go will share the same versioned OpenAPI and fixture contracts in this repository. All rights reserved; public source visibility is not a license grant.

```ts
import {createSierraClient, paginate} from '@sierragridteam/sdk';
const grid = createSierraClient();
const nodes = await grid.listEvents({layer:['MESH'], pageSize:50});
if (!nodes.notModified) console.log(nodes.data.events);
const topology = await grid.listMeshLinks({window:'72h'});
const archive = await grid.getMeshTelemetry({node:'1'.repeat(64),
  from:'2026-11-06T00:00:00Z', to:'2026-11-07T00:00:00Z'});
for await (const page of paginate(pageToken => grid.listHistory({
  from:'2026-11-06T00:00:00Z',to:'2026-11-07T00:00:00Z',pageToken
}))) console.log(page.revisions, page.nextPageToken);
```

Install with `pnpm add @sierragridteam/sdk`. ESM; modern browsers and Node 22+. Consumers choose their own rendering and chart libraries. No framework hooks or shared UI are included.

The facade includes `listEvents`, `getEvent(id)`, `getEventTimeline(id)`, `listRelatedEvents(id)`, `getEventHistory(id, query)`, `getEventSamples(id, query)`, `listHistory(query)`, `getStats(query)`, `getRoadHistory(road, query)`, `listPlaces`, `getPlace(place)`, `resolvePlace(query)`, `getPlaceSummary(place)`, `getConditions`, `listCameras`, `listScanners`, `listSources`, `getMapLayer(place, layer, query)`, `listMeshLinks`, `getMeshTelemetry(query)`, and `search(query)`. Query fields and response fields follow the API. Every response is Zod-validated. `@sierragridteam/sdk/generated` exposes the lower-level generated fetch SDK; `/schemas` exposes generated Zod schemas.

`createSierraClient({baseUrl, fetch, timeoutMs})` supports injected transports. The last argument of each method accepts `{signal, etag, timeoutMs}`. Default deadline is 20 seconds, covering body consumption. No requests retry automatically. `ApiResult` discriminates 304 (`notModified: true`, no data) from a validated body. `SierraApiError` preserves HTTP status, codeName, retryAfter and error body, including plain-text deployment failures. Schema validation errors remain Zod errors. Raw generated functions have their own Hey API result/error conventions; use the facade for consistent 304/deadline handling.

Geometry defaults to OBJECT; decimal int64 counters remain strings and nullable gauges remain null. Convert counters deliberately for charts. Event revisions use their declared numeric wire type. Event detail blocks are optional; narrow on layer and check the matching block. Missing, stale and unavailable data must not be presented as zero or an all-clear. Keep provenance/official-source links visible.

Enum fields of a response are open (0.5.0). The API adds values (a new event layer, source id, source or timeline kind, status, severity) without a breaking change, so a field such as `event.layer`, `event.status`, `provenance.sourceId`, `source.kind` or a timeline entry's `kind` may carry a value newer than this SDK: it validates and is delivered unchanged, and its type is the known values plus any string (`'WILDFIRE' | 'MESH' | ... | UnknownEnumValue`, where `UnknownEnumValue` is `string & {}`, so editors still complete the known values). Every `switch` or lookup on an enum field needs a `default` that handles a value it does not know (show it as written, or as "other"); never treat an unknown value as a known one, and never as an all-clear. A wrong type (a number where a string is expected) and a missing required field still fail validation; a missing enum is never filled in with an `*_UNSPECIFIED` default. Request enums are closed: the `layer`, `status`, `severityMin`, `kind` and `geometryFormat` query parameters and the map layer path parameter only accept values this SDK knows, so a value read from a response must be narrowed before it is sent back as a filter.

History requires explicit `from < to`. Pagination ends only at an empty continuation token. `paginate` yields at most 100 pages by default; if the final yielded page has a nonempty token, results are incomplete. It does not download unlimited archives. A short page is not the end. Telemetry is separately capped by the server: retain `coverage`, `truncated`, `cadenceSeconds` and `reboots` in analysis. History describes revisions, not continuously refreshed radio liveness; current liveness is lastRelayedAt/lastHeardAt.

Text search: `listEvents({q})` keeps events whose text matches and orders them newest first; the response then has `totalMatches` (every page), `counts` by layer and category, `matches[event.id]` (an excerpt as `parts` of plain text, `hit` marking the matched words: concatenate the parts, never treat them as markup) and `search` (how the query was read, `since`, and a `note` to show with the results). Without `q` those fields are `null` or empty. Pass `qTyping: true` only from a search-as-you-type box; `counts: true` returns the total without a text query. `listHistory({q, from, to})` matches each revision's text as it stood, and `collapse: 'event'` answers one row per event in `collapsed` (first and last matching revision). `search({q})` is the finder: the best few hits of each kind (`PLACE`, `ROAD`, `EVENT`, `MESH_NODE`, `CAMERA`, `SCANNER`), `totals` per kind and `unavailable` kinds that could not be searched; `hit.event` is null except for events and mesh nodes. No match means no stored report matched, not that nothing happened. While the service builds its index, `q` requests fail with `SierraApiError` 503: retry, and never render that as an empty result.

Revisions have a `kind` (0.6.0): `CHANGE` when an event's content or status changed, `READING` when a reading confirmed an unchanged state (each call to a county burn line). `getEventHistory` and `listHistory` return changes unless `kind: ['READING']` or `['CHANGE','READING']` is passed, so revision numbers in a default read can skip. `event.nature` is `OCCURRENCE` (something that happens) or `STATE` (the standing state of a tracked thing: a mesh node, a burn status, a feed's health, a monitored road); use it instead of a list of layers, for example to count what is happening. `event.readings` counts an event's readings; `getStats` splits `revisions` into `changes` and `readings`, overall and per layer. `q` cannot be combined with `kind: ['READING']` (400). Layers `SOURCE_HEALTH` (one event per upstream feed, `source:{id}`; its history is that feed's outages), `CHAIN_CONTROL` (one event per stretch under a chain requirement, the ids of the `chain_control` map layer) and `ROAD_SEGMENT` (one event per monitored road, revised when it closes or reopens) are ordinary events with `sourceHealth`, `chainControl` and `roadSegment` detail blocks. `getEventSamples(id, {from, to})` returns the series behind an event whose layer keeps one (a road's travel times in `road`); other layers answer 404.

`event.subhead` (0.7.0) is a short line saying what is particular to an event among events with the same headline (one of two "Winter Storm Warning" alerts: its elevation band and amounts); show it beside the headline, and nothing when it is empty. A monitored road that is not open says why in `roadSegment.causes` (0.8.0): each cause has the `status` it set, a `source` (`incident`, `lane_closure`, `road_condition`), the `eventId` of the incident behind it when there is one, and `text` only when the source wrote it (a Caltrans road condition); `listRelatedEvents` links the road and that event both ways. Against a Grid older than this snapshot `causes` is `undefined`. `getEventSamples(id, {from, to, maxPoints})` returns points shaped for a chart (0.8.0): `bucketSeconds` is 0 for raw samples or the width of each bucket, every point has `samples`, a mean `durationMinutes` with its minimum and maximum, and the most restrictive `status`; the figures are `null` while a road is closed; `coverage` and `gaps` say what the window holds, so an empty stretch is not read as calm.

## Shared synthetic fixtures

```ts
import {createSierraClient} from '@sierragridteam/sdk';
import {createFixtureFetch, FIXTURE_NOW, FIXTURE_LABEL, fixtureNodes} from '@sierragridteam/sdk/fixtures';
const grid = createSierraClient({fetch:createFixtureFetch({scenario:'partial'})});
// Display FIXTURE_LABEL prominently. Use FIXTURE_NOW as the demo chart clock.
```

Scenarios: `normal`, `empty`, `stale`, `partial`, `unavailable`. Six synthetic nodes include zero/null batteries, a sampling gap, reboot counter reset, unmonitored node and truncated archive. Links include an outside endpoint. A synthetic road incident, places and source states support context. These are invented fixtures, never a saved production response. `/fixtures` is a separate import so ordinary clients do not bundle demo data.

Fixture event filters support place/layer/status/severityMin/since, pageSize and pageToken, plus `q`, `qTyping`, `counts`, `collapse` and the finder. An unknown `layer`, `status` or revision `kind` is a 400, as in the API. Every fixture event has two `CHANGE` revisions; the road incident (`FIXTURE_READING_EVENT_ID`) also has one synthetic `READING` (revision 3, `readings: 1`), returned by either history route only when `kind` asks for readings, and `q` with `kind: ['READING']` is a 400. No fixture event is a `ROAD_SEGMENT`, so `getEventSamples` answers the API's 404 for the event's layer instead of an invented road series. Fixture text search is an approximation (whole words of the headline, location, summary, description and node name; no stemming and no road spellings), enough to build and test a search UI against. History applies explicit time bounds and event filters; telemetry applies bounds and preserves overall coverage. Fixtures use indexed continuation tokens (not the server's opaque keyset implementation); do not reuse a token with changed filters. Partial scenarios deliberately produce short pages and telemetry truncation; Valley Relay (`fixtureNodes[2]`) telemetry fails with JSON 503 while other nodes succeed. Unavailable returns JSON 503 for event lists/details/history and telemetry, and plain-text 503 for links; each includes Retry-After. Source diagnostics and map metadata remain readable as UNAVAILABLE. Stale exercises source-health freshness: source/summary last-success and map last-update are two days before FIXTURE_NOW, with STALE status. Event and telemetry fixture series remain the shared deterministic dataset rather than being rewritten by this source-health scenario. Only OBJECT geometry is supported. Fixture topology durations support h/m/s units. Only mesh_node, mesh_link and road_incident map layers are implemented; other layers return 404 rather than a misleading healthy empty map. Address resolution, other unimplemented endpoints and unsupported parameters return explicit errors. Fixtures are not a general replacement server; conditions/camera/scanner datasets are intentionally empty. They perform no network requests.

## Maintenance and provenance

- `schema/openapi.json` is the immutable upstream snapshot; `schema/source.json` records source commit and SHA256, which generation verifies against the exact snapshot bytes. A `note` in `schema/source.json` means the pinned commit is not yet on sierra-data `main`.
- `scripts/prepare-schema.mjs` creates the generation-only overlay: public data GETs only; URI annotations become strings because protobuf defaults allow empty strings; int64/uint64 formats retain declared JSON type rather than Hey API's default BigInt coercion (decimal strings gain signed/unsigned patterns while existing tighter patterns are retained). No upstream file is rewritten.
- Tolerant response enums are made in the same overlay (`tolerateResponseEnums` in `scripts/schema-contract.mjs`), not by rewriting generated code: every string enum reachable from a response body, whether a named enum schema or a closed list on a plain string property, becomes `anyOf: [the known values, UnknownEnumValue]`, which Hey API renders as an ordinary Zod union and TypeScript union. The single edit of generated output is in `scripts/finalize-generated.mjs`: the alias `UnknownEnumValue = string` becomes `string & {}`, and generation fails if that line is not found exactly once. Kept strict on purpose: request parameters (never walked; a schema they refer to is copied inline first); the GeoJSON tags `MapFeature.type`, `MapFeatureCollection.type` and `MapGeometry.type` (a different value is a different shape); integer constants such as `schemaVersion` (a new version is a new contract); and schemas no GET response reaches (ingest payloads, JSON-RPC). Relaxed enums also lose their protobuf zero-value `default`, so a missing enum fails or is `undefined` instead of being invented.
- Fields added since the previous release: the API marks every response field required, so a field it only just started sending would make this SDK reject a Grid one deployment behind. `FIELDS_ADDED_SINCE_PREVIOUS_RELEASE` in `scripts/schema-contract.mjs` is the short explicit list of such fields, generated as optional (currently `v1Event.readings`, `v1EventRevision.kind`, `v1Stats.changes`, `v1Stats.readings`, `v1LayerStats.changes`, `v1LayerStats.readings`). An entry is deleted, and the field is required again, once no supported server lacks it; an entry that no longer names a required property fails generation.
- Hey API `0.99.0` and Zod `4.6.7` are pinned. Generated imports are normalized to explicit ESM extensions. `fixtures/scenarios.json` is the language-neutral synthetic data source.
- `pnpm install --frozen-lockfile`, `pnpm verify`, `pnpm drift`; optional `pnpm smoke` performs three small public GETs. CI never needs API credentials.
- Regenerating: copy the new `openapi.json`, update `schema/source.json` (commit and SHA256), `pnpm generate`, `pnpm verify`. Release checklist: (1) `schema/source.json` pins a commit that is on sierra-data `main`: if it has a `note` saying it pins an unmerged branch commit, re-pin to the merged commit (and its snapshot) and remove the note first; (2) compare the `required` lists of response schemas with the previous release's snapshot and put newly required properties in `FIELDS_ADDED_SINCE_PREVIOUS_RELEASE`, removing entries every supported Grid now sends; (3) run the example/fixture/transport checks and review drift; (4) add the release to `CHANGELOG.md`. Upstream schema fixes belong in sierra-data; generation accommodations are documented here.
- Future Python and Go packages belong under `packages/python` and `packages/go`, each with its own release workflow. They must preserve these same wire/nullability, pagination and coverage semantics. No placeholder package claims those implementations exist.

Build/package only includes `dist` plus package metadata/readme. No credentials, live captures, servers, or internal workspace files belong in this repository or the npm tarball. Releases require review. `.github/workflows/publish-typescript.yml` publishes only an explicit `typescript-vX.Y.Z` tag (or manual dispatch selecting that existing tag), validates package/tag equality, and uses npm trusted publishing with provenance. Configure the `npm` GitHub environment and npm trusted publisher for this exact workflow before a release. Python/Go will use separate tag namespaces and workflows. No long-lived npm credential is stored.
